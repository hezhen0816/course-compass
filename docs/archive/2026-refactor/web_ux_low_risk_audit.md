# Web UX Low-Risk Audit

日期：2026-06-12

狀態：歷史 audit。2026-06-13 起，使用者確認式官方選課送出已實作；這份文件保留當時低風險 UX 觀察，現況以 `README.md`、`docs/architecture/refactor-plan.md` 與 `docs/data-contracts/database-schema.md` 為準。

方法：使用 Product Design 檢查角度，檢查實際開啟的 `http://localhost:5173/` Web 介面。

歷史範圍：只檢查當時 Web 體驗與流程，不調整資料結構、不新增官方送出選課能力。

實際觀察：
- 已登入帳號：`hezhen0816@gmail.com`。
- 主畫面顯示「已完成 0 / 0 個待修需求，已安排 57 學分」。
- 左側包含畢業門檻、PDF 匯入、手動查課、待修需求池。
- 右側是學期週課表，目前大一上安排 9 門課、21 學分。
- 「同步校務資料」modal 會要求校務帳號密碼，文案說明會取得選課清單、歷年成績並補查歷史節次。
- 手機寬度下內容會單欄堆疊，週課表仍是完整 7 天橫向表格。
- 手動搜尋「資料結構」可列出多筆課程，提供「加入待修」與「排入課表」。

## 1. 把「手動查課」升級成「課程查詢」入口

目前「手動查課」其實已經是官方選課輔助方向的核心：可以用課名/課碼查詢，結果列出課碼、教師、學分、節次，並能加入待修或排入課表。但它放在左側工具區，標題也偏內部功能名，容易被理解成補資料的小工具。

建議：
- 將標題從「手動查課」改成「課程查詢」或「官方課程查詢」。
- 將「查詢學期」下拉移入這張卡片，讓學期、課名/課碼、搜尋框形成同一個查詢表單。
- 搜尋結果上方顯示摘要，例如「1151・課名：資料結構・7 筆結果」。
- 空搜尋時停用「查詢」按鈕，避免送出無意義請求。

低風險原因：只改 UI 分組、文案與 disabled 狀態，不改 API、不改資料結構。

驗證：
- 搜尋「資料結構」仍列出目前 7 筆結果。
- 「加入待修」與「排入課表」行為不變。
- 空 query 不送出查詢。

## 2. 同步校務資料 modal 補足信任文案

同步 modal 現在有說「取得最新選課清單、歷年成績，並自動補查可辨識的歷史節次」，但它要求輸入校務系統帳密，使用者會自然擔心密碼是否保存、會改哪些資料、是否會覆蓋現有 Web-only 欄位。

建議：
- 在密碼欄位下方加短文案：未保存時密碼僅用於本次同步；若選擇保存，會由後端加密寫入 `public.school_credentials`。
- 在送出按鈕上方列出同步會做的三件事：更新目前選課清單、匯入歷年成績、補查歷史節次。
- 加一行保守界線：「不會自動送出選課、不會排程重試。」

低風險原因：只補說明文字，不改同步邏輯。

驗證：
- modal 仍可送出同步。
- loading、success、error 狀態不被新文案擠壓。

## 3. 週課表加入圖例與手機橫向提示

目前課程卡片用顏色區分類別，衝堂也會用紅色背景，但畫面上沒有圖例。手機寬度下週課表仍是完整橫向表格，功能可用，但沒有提示使用者可左右滑動。

建議：
- 在「學期週課表」標題區加一列小型圖例：本系必修、本系選修、通識、雙主修、衝堂。
- 在手機寬度下，課表上方顯示「課表可左右滑動」。
- 保留目前 `min-w` 橫向課表，不重做排版。

低風險原因：新增說明性 UI，不改排課演算法、不改課程資料。

驗證：
- 桌面版圖例不壓縮學期按鈕。
- 手機版提示與課表不重疊。
- 衝堂判斷仍沿用現有邏輯。

## 4. 課程卡片刪除降低誤觸風險

週課表中的課程卡片整張可點開 detail，右側垃圾桶可直接移除課程。這在密集課表上效率高，但手機或觸控操作容易誤刪。

建議：
- 點垃圾桶後加一個輕量確認，例如「移除這門課？」。
- 或把刪除動作移到 `CourseDetailModal`，週課表卡片只負責開啟詳細資訊。
- 若保留卡片刪除，至少讓垃圾桶在 hover/focus 時更明確，並改善可點區域分隔。

低風險原因：只調整刪除互動，不改課程資料模型。

驗證：
- 點課程卡仍開 detail。
- 刪除後學分統計與課表即時更新。
- 鍵盤 Enter/Space 開 detail 的行為不變。

## 5. 待修需求池改善空狀態與下一步指引

目前待修需求池顯示「0 份規則，0 個需求，已匯入 21 筆修課紀錄」以及「尚未匯入待修需求」。這是準確的，但使用者下一步不夠明確：是要上傳 PDF、手動查課，還是同步校務？

建議：
- 空狀態改成兩個明確 action：上傳 PDF、從課程查詢加入待修。
- 保留目前匯入歷史紀錄數字，但把它當成背景資訊，不當成主要狀態。
- 未來有需求後，再加「全部 / 未完成 / 已完成 / 待重修」filter chips。

低風險原因：先改善空狀態與導流，不先做資料篩選。

驗證：
- 未匯入 PDF 時空狀態仍顯示。
- 點 action 只聚焦到既有上傳或搜尋區，不新增資料寫入。

## 建議實作順序

1. 課程查詢入口整理。
2. 同步 modal 信任文案。
3. 週課表圖例與手機提示。
4. 待修需求池空狀態。
5. 課程刪除確認。

第一個 checkpoint 建議只做 1、2、3。這三項最貼近「Web 規劃工具 + 官方選課輔助介面」方向，而且完全不需要碰 Supabase schema、iOS model 或 backend parser。
